## MANDATORY REVIEW CHECKLIST

### 1. Kotlin Style, Type Safety & Static Analysis (Detekt / Ktlint)
- **Complete Production Code Only:** NO stubs, `TODO()`, placeholder code, dummy implementations, or `// ... rest of code`.
- **Explicit API Mode:** All public declarations and companion objects in public classes MUST specify explicit visibility (`public`).
- **NO Trailing Commas** at the end of argument, parameter, or entry lists.
- **NO Inline Implementation Comments (`//`, `/* ... */`) or Agent-Generated `TODO`/`FIXME`:** Logic must be self-documenting via expressive naming and private helper decomposition. Preserve pre-existing developer `// TODO:` / `// FIXME:` comments unless resolved by the task. **NEVER delete, strip, or omit KDoc (`/** ... */`).**
- **NO Fully Qualified Names (FQN):** Forbidden in expressions, type annotations, generics, and KDoc links. Use `import` or `import ... as ...` aliases. Permitted ONLY inside `@Deprecated(..., replaceWith = ReplaceWith(...))` import parameters or when technically unavoidable (must be explicitly justified).
- **Single Declaration Per File:** Every primary public `interface`, `class`, or `object` MUST reside in its own file matching its declaration name. Exceptions apply ONLY to direct subtypes of a `sealed` hierarchy and top-level extension parsers/constants directly bound to a `value class` in the same file.
- **Strict Prohibition of `!!`:** Non-null assertion (`!!`) is strictly forbidden in production code (allowed ONLY in test files). Use `?.`, `?:`, `as?`, smart-casts, or `requireNotNull(...)` / `checkNotNull(...)` with descriptive messages only for unrecoverable invariants.
- **NO `println`:** Prohibited in production code (`ProhibitPrintln`).
- **Control Flow (`when` & `if`):**
  - NO function or suspend invocations inside `when (...)` parentheses and NO `when (val x = someCall())`. Extract the call to a `val` on the preceding line first.
  - Exhaustive `when` on `sealed` types and `enum`s without `else` unless logically unavoidable.
  - Mandatory `{ ... }` block braces for all `if` statements (NO single-line `if (cond) return`; put `return` on its own line inside braces).
- **Naming & Function Bodies:**
  - Use concrete, domain-specific outcome variable names (e.g., `validationResult`, NOT `result` or `data`).
  - Simple mappers/transformations use expression-body (`=`); multi-step or branching logic uses block-body (`{ ... }`).
- **Companion Objects:** Place at the bottom of the class body (unless implementing `NavigationScreenParamsParser<P>`). Extract constants as `public const val` inside `public companion object`.
- **Inline Value Classes (`@JvmInline value class`):** Domain IDs/wrappers MUST be `@Serializable`, expose a public `.value` property, provide `asString()` (or `asHexDashString()`), `generate()` in companion (when applicable), and `String.toXxxOrNull()` / `String.toXxxOrThrow()` extension functions in the same file.
- **Wire Value Property:** Domain enums and extensible interfaces MUST expose `.value` for wire string representation (NEVER `.serialName`).

### 2. Entity Projections, Serialization, Errors & WebSockets
- **Up to 4-Tier Projections:** `Summary`, `Details` (optional—omit if `Summary` suffices for public view), `Private`, `Internal`. Never invent ad-hoc suffixes (`*Full`, `*View`, `*Admin`, `*Extended`).
- **STRICT PROHIBITION on `*InternalPayload`:** NEVER create an `[Entity]InternalPayload` DTO or serialize/expose `Internal` models over HTTP/WebSocket APIs.
- **Mappers:** Provide `*SummaryMapper.kt`, `*DetailsMapper.kt` (if `Details` exists), `*PrivateMapper.kt`, and 1-step `*DomainMapper.kt` (`Internal -> Private`, `Internal -> Summary`, `Private -> Summary`, etc., without intermediate allocations). Extract an optional base `[Entity]` interface if multiple projections share validation/helper logic.
- **Serialization (`kotlinx.serialization`):** Always use `FoundationJson` (`snake_case`, `ignoreUnknownKeys`, `encodeDefaults`). Every DTO property MUST use `@SerialName` referencing constants from `*ApiFields`. Apply `@RequiredField` / `@NotBlankStringField` hints where applicable.
- **Error Contracts:** Use `ApiErrorResponse` wire shape. Define ONLY machine-readable code strings (`*ErrorCodes`) and argument keys (`*ErrorArgs`). NO human-readable/localized strings in error contracts.
- **WebSockets:** Use `SocketFrame` with `payload: JsonElement?` and `*WebSocketEventTypes` constants.
- **Audit & Extensibility:** Account for `AuditValueSensitivity` (PII redaction), use `CompositeAudit*Parser` for extensible domain types, and use `*AuditMetadataKey` for metadata.
- **Backward Compatibility:** Flag any breaking change to public DTOs, payloads, routes, error codes, or Zod contracts.

### 3. Filtering, Sorting, Navigation, Localization & UI Configs
- **Flat Top-Level Filter/Sort Types:** Filter objects MUST be top-level `object [Entity]FilterValues` and sort enums MUST be top-level `@Serializable enum class [Entity]SortBy(val value: String)` (NO redundant nested wrapper objects).
- **Filter Ordering & Primary Key Ban:**
  - Constants in `[Entity]FilterValues` MUST strictly follow the property declaration order of `[Entity]Private`.
  - NEVER include an entity's own primary `id` / `[ENTITY]_ID` in its collection list `[Entity]FilterValues` (foreign keys/parent IDs are allowed; batch IDs only on explicit batch endpoints).
- **Filter Semantics:**
  - Selective presence filters (`IS_*_SET`) ONLY for nullable fields representing distinct business states (no redundant flags).
  - Numeric/temporal fields use range bounds (`*_FROM`/`*_TO` inclusive; `*_GT`/`*_LT` exclusive).
  - String identity fields strictly separate exact match (`FIELD`), substring (`FIELD_CONTAINS`/`*_LIKE`), and `SEARCH_QUERY` (route KDoc MUST list target fields).
  - Booleans use exact match (`is_*`), distinct from presence (`is_*_set`).
  - Collections/enums: base key = OR, `*_ALL` = AND, `EXCLUDE_*` = NOT IN. Nested fields flattened with underscores.
  - Sorting uses `sort_by` + `sort_order` (`SortOrder`); defaults: temporal = `DESC`, alphabetic = `ASC`, fallback = `CREATED_AT` + `DESC`.
- **Navigation Layer:** `*Navigation` objects implement `NavigationRoute`, `ParameterizedNavigationRoute<P>`, or `RedirectNavigationRoute`; `*Params` implement `NavigationScreenParams`; `*ParamsParser` implement `NavigationScreenParamsParser<T>` using `QueryParamNormalizer` / `PhoneParamNormalizer`.
- **Localization Resources:** Flat JSON in `src/commonMain/resources/localization/<group>/<module>/<locale>/<bundleName>.json`, strict `snake_case` keys, `{paramName}` placeholders, `_without_args` / `_with_args` pairing when both static and parameterized variants exist.
- **UI Values & Configs:** Pure non-localized `UiValues` in `core/common`; pure data classes for `*UiConfig` without UI framework dependencies.
