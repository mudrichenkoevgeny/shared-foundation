# API Documentation Standard (Routes & Contracts)

This document defines the strict KDoc requirements for all API route constants. Adhering to this structure ensures that server and client implementations remain synchronized and that security/audit requirements are visible at the contract level.

## 1. Documentation Hierarchy
Every callable endpoint must follow this exact order. Sections should be omitted only if they are not applicable to the specific route.

### I. Header & Description
* **HTTP Method:** `**HTTP method:** METHOD` (e.g., `GET`, `POST`, `PATCH`, `DELETE`).
* **Summary:** A concise one-sentence description of the endpoint's purpose.
* **Notes:** (Optional) Use `**Note:**` to describe internal business logic validations that aren't captured by the authorization filter (e.g., "validates that email belongs to staff").

### II. Request Contract
* **Path parameters:** Reference the constant used in the path.
  * *Format:* `Path parameter: [DomainApiPaths.PARAM_ID].`
* **Query parameters:**
  * **Pagination & Sort:** Reference `[ListingParamNames]`.
    * *Note:* `page` index is **one-based** (`1` = first page).
  * **Filters:** Reference the domain-specific filter values (e.g., `[UserFilterValues.UserFilterValues]`).
  * **Filter Logic:** **Repeated keys = OR**, **Different keys = AND**. Absent parameters = no filtering.
* **Request body:** Reference the input DTO.
  * *Format:* `Request body: [SomeRequestPayload].`

### III. Response Contract
* **Response body:** Reference the output DTO.
  * *Format:* `Response body: [SomeResponsePayload].`

### IV. Access Control
* **Authorization:** Detailed breakdown of access requirements:
  * **Public Access:** `Allowed` for unauthenticated routes, `Denied` for all others.
  * **Allowed Roles:** List of `[UserRole]` with `(**OR** semantics)`.
    * *Exception:* If `Public Access` is `Allowed`, state `Any`.
  * **Allowed Account Statuses:** List of `[UserAccountStatus]` with `(**OR** semantics)`.
    * *Exception:* If `Public Access` is `Allowed`, state `Any`.
  * **Required Permissions:**
    * For static requirements: List `[PermissionCode]` with `(**AND** semantics)`.
    * For dynamic requirements (e.g., `PATCH`): Define permissions per provided field in the request body.
    * If none, state `None`.
  * **Authority Level:** (For Management APIs) Define hierarchical requirements (e.g., "Actor's level must be strictly greater than the target's level").
* **Security:** Notes on sensitive operations (e.g., **MFA Step-up**, **TOTP confirmation**, or **Re-authentication** requirements).

### V. Accountability (Observability)
* **Audit logging:** Describe the `[AuditEventPrivate]` generated by this route:
  * **Event Condition:** (e.g., "for successful execution and all failed attempts").
  * **Action:** Reference `[DomainAuditActionType]`.
  * **Actor:** Define `actorId` source (e.g., "the administrator performing the update").
  * **Resource:** Define `resourceId` source.
* **Metadata:** Use a numbered list for keys:
  1. `[MetadataKey]` — description of the value source.

### VI. Navigation Traceability (UI Presentation)
* **UI Presentation:** Reference the UI screens or flows where this API endpoint is consumed:
  * Format: Always start with `**UI Presentation:**` followed by bulleted items for `- Screens:` and optional `- Flow:`:
    ```kotlin
    /**
     * **UI Presentation:**
     * - Screens:
     *   - [ManagementAuditNavigation.AuditEventList]
     */
    ```
  * For background-only routes without dedicated UI screens:
    ```kotlin
    /**
     * **UI Presentation:** None.
     */
    ```
  * For routes associated with global flows or dialogs (no standalone screen):
    ```kotlin
    /**
     * **UI Presentation:**
     * - Screens: None.
     * - Flow: Global re-authentication dialog (no dedicated screen).
     */
    ```

## 2. Navigation Screen KDoc Standards

All navigation screen objects (`XxxNavigation`) must adhere to this standard for `Primary API` and `Secondary Action APIs`:

1. **Primary API:**
   - For **Listing and Detail screens**: The principal HTTP API endpoint executed automatically upon screen mount/initialization to load primary screen data (e.g., `GET /management/audit/events` or `GET /management/users/{user_id}`).
   - For **Form/Auth screens**: The principal HTTP API endpoint executed when submitting the primary action of that screen (e.g., `POST /auth/register/email` or `POST /auth/login/email`).
   - If no auto-fetch or primary form submit exists on the screen, mark as `None.`

2. **Secondary Action APIs:**
   - Auxiliary HTTP API endpoints triggered by user interaction buttons on the screen (e.g., resending OTP confirmation codes, restoring an account, logging out, toggling 2FA mode, or deleting a resource).
   - If multiple auxiliary actions exist, format as a bulleted list on new lines:
     ```kotlin
     /**
      * **Secondary Action APIs:**
      * - [OpenUserRoutes.RESTORE_USER]
      * - [OpenSessionRoutes.LOGOUT]
      */
     ```
   - If no auxiliary actions exist, mark as `None.`

## 3. Example: Dynamic Management Route
```kotlin
/**
 * **HTTP method:** `PATCH`
 *
 * Partially updates user account details: status, authority level, or permissions.
 *
 * Path parameter: [UserApiPaths.USER_ID].
 *
 * Request body: [UpdateUserRequest].
 *
 * **Authorization:**
 * - **Public Access:** Denied.
 * - **Allowed Roles:** [UserRole.STAFF], [UserRole.ADMIN] (**OR** semantics).
 * - **Allowed Account Statuses:** [UserAccountStatus.ACTIVE] (**OR** semantics).
 * - **Required Permissions:** Required permissions depend on the fields provided in [UpdateUserRequest] 
 *   and the target user's role (**AND** semantics for all provided fields):
 *   - If [UpdateUserRequest.accountStatus] is set: 
 *     - [UserPermissionCode.USER_UPDATE_STATUS_FOR_USER] (target: [UserRole.USER])
 *     - [UserPermissionCode.USER_UPDATE_STATUS_FOR_STAFF] (target: [UserRole.STAFF])
 *   - If [UpdateUserRequest.authorityLevel] is set:
 *     - [UserPermissionCode.USER_UPDATE_AUTHORITY_FOR_USER] (target: [UserRole.USER])
 *     - [UserPermissionCode.USER_UPDATE_AUTHORITY_FOR_STAFF] (target: [UserRole.STAFF])
 * - **Authority Level:** Actor's level must be strictly greater than the target's level. 
 *   Actor cannot target own account.
 *
 * **Security:** Sensitive operation. MFA Step-up required. Returns 
 * [SecurityErrorCodes.MFA_CONFIRMATION_REQUIRED] if additional verification is needed.
 *
 * **Audit logging:** Persist an [AuditEventPrivate] for successful execution and all failed attempts.
 * - **Action:** [UserAuditActionType.MANAGEMENT_UPDATE_USER].
 * - **Actor:** [AuditActorType.USER]. Set `actorId` to the administrator performing the update.
 * - **Resource:** [UserAuditResourceType.USER]. Set `resourceId` to the [UserApiPaths.USER_ID].
 * - **Metadata:**
 *   1. [ClientInfo] — technical client details.
 *
 * **UI Presentation:**
 * - Screens:
 *   - [ManagementUsersNavigation.UserDetail]
 */
const val UPDATE_USER = ManagementUsersRoutes.UPDATE_USER
```
